# ZhuyuanTools・小小ㄉ工具箱

專門針對自己造出一個比較好用的輪子出來 owo，希望對你也有一點幫助。

本機工具箱：所有處理都在使用者自己的瀏覽器裡完成，檔案不會上傳到任何伺服器。

張（連拍放在一起），互相比較，每張給「可以放／要看一下／不能放」（或「精選／備選／不要」、「第一／備選／不要」）和具體的理由，不給星星。畫面：左邊是組（縮圖、時間、說了什麼），中間一組並排（連拍同色標記，每張下面是建議和理由，`Z` 或空白鍵放大），下面是這組的總評和按鈕，右邊是「我的標準」、分析進度、統計。沒有任何東西會自動標：`Enter` 照建議標好這組（留用、排除，「要看一下」不動）並到下一組，或「全部照建議」；`P` `X` `U` 一張張改，`⌘Z` 復原。結果記在瀏覽器（IndexedDB），標準改了會標「舊」並可以重看；到挑照片時，照片資訊會多一行 AI 說的。AI 經由本站轉送（`server/ai.js`，/pick/api/ai/…），要邀請碼；AI 的位址、金鑰、邀請碼只放在這台機器的 `server/data/ai.json`（不進 git）。傳給 AI 的只有長邊 768 px 的縮圖，不保存。

檢視下載（第三步）：大家出圖時已經自己分好資料夾（攤位、議程、幕後花絮…），挑照片不會動到它們，所以這一步像 Finder 一樣照原本的資料夾看挑好的：左邊是資料夾樹（每個資料夾挑到幾張，可以展開收起），右邊是打開的資料夾（先資料夾、再照片；圖示或列表，列表可以照名稱、拍攝時間、大小排），上面是 ‹ › 上一個／下一個和資料夾名稱，下面是路徑（點了回到那層）和張數。按兩下打開資料夾，`⌘↑` 回上一層（剛出來的那個資料夾會選好）、`⌘[` `⌘]` 上一個／下一個；照片像 Finder 一樣選（點一下、`Shift` 一段、`⌘` 多一張；平板點資料夾打開、點照片加選）；空白鍵或按兩下是 Quick Look（先放縮圖，再換第二步 worker 做的預覽，沒有就原圖，`←` `→` 換張），`P` `X`（`Delete`）`U` 一樣能改旗標（`⌘Z` 復原），沒挑的會離開；「顯示沒挑的」打開時沒挑的淡淡地列出來。存：照原本的資料夾存（整個，或下面的「只存這個資料夾」），標「留用」的或沒標「排除」的，ZIP 用最上層資料夾的名字。電腦版 Chrome、Edge 存進選的資料夾（已經在裡面的同一張跳過，可以分次存），其他瀏覽器打包 ZIP（從 ZIP 來的照片原封不動搬過去，不重新壓縮），只有一張就直接下載那張。電腦和平板限定：手機（觸控、小螢幕，跟首頁同一個判斷）首頁不放它（卡片、拖放區圖示、「要做什麼？」的選項、拖 ZIP 都不會給它），直接打開 `/pick` 只顯示「照片挑選要用電腦」和網址 |

## 執行

```bash
node server/server.js            # http://127.0.0.1:8080/
PORT=8090 HOST=0.0.0.0 node server/server.js
```

不需要安裝任何套件。正式機用 systemd 的 `manytools.service`（port 8090），再由 Cloudflare Tunnel 接到 https://tools.zhuyuan.tw/ 。
舊網址（`/home/index.html`、`/videotools/`、`/pdftools/local/`）和資料夾名稱（`/watermarktools/`、`/exiftools/` 等）會自動轉到新網址。
各工具的 `index.html` 也可以直接雙擊開啟（這時首頁不會顯示處理數量）。

## 計數

只記錄數量，不記錄檔名或內容，存在 `server/data/stats.json`（可用 `STATS_FILE` 改位置）。

- `GET /api/stats` → `{ video: { files, seconds, savedBytes }, pdf: { files, pages, savedBytes } }`
- `POST /video/api/stats/processed`、`POST /pdf/api/stats/processed`、`POST /avatar/api/stats/processed`、`POST /image/api/stats/processed`、`POST /crop/api/stats/processed`、`POST /watermark/api/stats/processed`、`POST /exif/api/stats/processed`、`POST /rename/api/stats/processed`（改名的檔案數，不加進首頁的數字）、`POST /pick/api/stats/processed`（挑好存下來的照片數，也不加進首頁的數字）
- 首頁的「頭貼」數量是查詢（avatar）加裁切（crop），「PDF」數量是壓縮（pdf）加浮水印（watermark），「圖片」數量是壓縮（image）加看參數（exif）

## Flickr 查詢

- `GET /exif/api/flickr/status` → `{ key: true | false }`
- `GET /exif/api/flickr/rest?method=flickr.photos.getInfo&photo_id=…` → Flickr API 的回答（伺服器加上金鑰；只允許照片參數查看用到的公開、唯讀方法）
- `GET /exif/api/flickr/oembed?url=<Flickr 連結>` → Flickr oEmbed（不需要金鑰）
- 答案暫存在記憶體（10 分鐘到一天，看是什麼），每個訪客 10 分鐘內最多 400 次新的查詢，全部加起來一小時 3,300 次（Flickr 一把金鑰一小時 3,600 次）

## 影片工具的技術重點

- 解析／封裝：[Mediabunny](https://mediabunny.dev/) 1.60.0（MPL-2.0），放在 `videotools/lib/`。
- 編解碼：瀏覽器內建 WebCodecs，有硬體加速就用硬體。需要 Chrome / Edge 94+，並且是 `https://`、`http://localhost` 或直接開檔（`file://`）；用 `http://` 加區網 IP 開啟時瀏覽器會擋掉編碼功能。
- 支援輸入：MP4、MOV、MTS / M2TS、MKV。MXF 目前不支援。
- Chrome / Edge 會讓使用者選一個輸出資料夾，直接串流寫到硬碟，幾 GB 的檔案也不會塞爆記憶體；其他瀏覽器則在記憶體裡組好再下載。
- 輸出影像為 8-bit 4:2:0；聲音預設原樣保留（LPCM / AAC 都不重壓）。
